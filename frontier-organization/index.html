Operating model

Persistent definitions. Ephemeral teams.

The organization exists as versioned policy and contracts. Agent instances are recruited for the objective, operate inside explicit authority, and dissolve when the evidence gate passes.

01

Portable organization

YAML or TOML defines roles, authority, model policy, recruitment rules, budgets, and typed work contracts. The definition belongs to you—not to an agent vendor.

02

Durable process

Temporal owns workflow history, timers, retries, signals, approvals, task queues, and recovery across worker crashes or long human decisions.

03

Cognitive orchestration

LangGraph decomposes objectives, recruits roles, fans work into subgraphs, merges evidence, and makes explicit conditional transitions.

04

Cross-model swarm

Architects, researchers, builders, critics, and evaluators are selected by capability. Critics should use a different model family from proposers.

05

Model plane

LiteLLM normalizes invocation, routing, fallback, limits, and accounting while a capability registry preserves meaningful provider differences.

06

Tools and isolation

An MCP host governs focused tool servers. Coding workers receive separate worktrees or containers and return patches to one integration owner.

07

State and evidence

Temporal stores execution history; PostgreSQL stores jobs and organizational memory; the artifact store retains sources, reports, patches, and tests.

08

Evaluation and telemetry

Deterministic tests and policy checks gate completion. OpenTelemetry correlates traces, metrics, and logs across every runtime boundary.
